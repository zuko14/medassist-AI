# Kriya Diagnostic OS — Forensic Re-audit (design vs. code)

> Part of the Diagnostic OS set: start at [status.md](status.md). Audit date **2026-11-05**, code at `main` @ `56f719f`.
> Purpose: every claim an implementing agent will rely on was re-checked against the code; every finding below names
> the evidence (file:line at `56f719f`), its severity, and where the design was corrected. **If a line number has
> moved, re-locate by the quoted symbol; never guess.** Inputs: owner screenshots of MocDoc (order list, expanded
> visit, Print Barcode dialog), the Taiyo Labs report, the owner's requirements of 2026-11-05 (insurance/TPA patients
> must not receive reports; unpaid bills must never release a report automatically).

Severity: **Critical** = would leak a report or release it without payment · **High** = data corruption, bypass of a
clinical control, or silent non-delivery · **Medium** = wrong behaviour in a real scenario · **Low** · **Correction**
= a factual error in the first draft of these docs.
